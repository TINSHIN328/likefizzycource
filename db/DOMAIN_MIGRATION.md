# Domain Migration Guide

## Проблема

Старые пользователи все еще используют домен `mail.mooissha` в своих настройках, потому что:

1. **При создании записей** система использовала `domains[0]` из config.json
2. **Домен был изменен** в config.json с `mail.mooissha` на `protonautosecure.bond`
3. **Старые записи в БД** не обновились автоматически

## Где хранятся домены

### 1. **secureconfig** таблица
- Поле `domain` - домен для secure операций
- Используется при создании security emails

### 2. **autosecure** таблица  
- Поле `domain` - домен для каждого бота
- Каждый бот может иметь свой домен

### 3. **registeredemails** таблица
- Поле `email` - полный email адрес (включая @domain)
- Используется для приема уведомлений

### 4. **email_notifier** таблица
- Поле `email` - email для уведомлений
- Аналогично registeredemails

### 5. **accounts** таблица
- Поле `secemail` - security email защищенных аккаунтов
- Это реальные email адреса Microsoft аккаунтов

## Решение

### Шаг 1: Проверка текущего состояния

Запустите скрипт проверки, чтобы увидеть сколько записей с старым доменом:

```bash
node db/check_domains.js
```

Этот скрипт покажет:
- Сколько записей в каждой таблице используют старый домен
- Примеры записей (первые 5)
- Общее количество записей требующих обновления

### Шаг 2: Миграция доменов

После проверки, запустите миграцию:

```bash
node db/migrate_domains.js
```

Этот скрипт:
- ✅ Обновит домен в таблице `secureconfig`
- ✅ Обновит домен в таблице `autosecure`
- ⚠️  Покажет emails в `registeredemails` (требует ручной проверки)
- ⚠️  Покажет emails в `email_notifier` (требует ручной проверки)

### Шаг 3: Ручная проверка email адресов

**ВАЖНО:** Таблицы `registeredemails`, `email_notifier` и `accounts` содержат **реальные email адреса**.

Их нельзя автоматически обновлять, потому что:
- Это настоящие адреса пользователей
- Могут быть важны для получения OTP кодов
- Пользователи должны сами их обновить

## Настройка для новых пользователей

Убедитесь что в `config.json` первый домен актуальный:

```json
{
  "domains": ["protonautosecure.bond"],
  ...
}
```

Новые пользователи автоматически получат этот домен.

## Как пользователи могут обновить свой домен

### Для Secure Config:
Используйте команду `/settings` -> "Change Email Domain"

### Для Autosecure бота:
Используйте кнопку "Change Domain" в настройках бота

### Для регистрации нового email:
Используйте команду `/email register` с новым доменом

## Дополнительная информация

### Почему это произошло?

В базе данных есть DEFAULT значения:
```sql
domain TEXT DEFAULT '${config.domains[0]}'
```

Когда `domains[0]` изменился в config.json, DEFAULT значение для **новых записей** обновилось, но **существующие записи** остались со старым доменом.

### Как предотвратить в будущем?

1. Не меняйте домены в production без миграции
2. Используйте отдельную конфигурацию для доменов
3. Добавьте version tracking для config.json
4. Создавайте миграции для критических изменений

## Безопасность

⚠️ **ВАЖНО**: Перед запуском миграции:

1. Сделайте backup базы данных:
   ```bash
   cp store/database.db store/database.db.backup
   ```

2. Проверьте что новый домен правильно настроен
3. Убедитесь что MX записи для email работают
4. Проверьте SMTP сервер настроен на новый домен

## Troubleshooting

### Миграция не обновляет записи?

Проверьте:
- Путь к базе данных правильный
- У скрипта есть права на запись
- База данных не заблокирована другим процессом

### Emails все еще не работают?

Проверьте:
- DNS MX записи для нового домена
- SMTP сервер принимает почту на новом домене
- Нет конфликтов портов (25, 587, 465)

### Нужна помощь?

1. Проверьте логи: `logs/`
2. Посмотрите текущий config: `cat config.json`
3. Проверьте базу данных: используйте SQLite browser
